## 读 `decisions.md` 之前

它是**按轮次追加的日志**，不是一份整理过的设计文档。所以：

- **条目编号（`§N`）永不重排**，代码注释里到处引用它们。哪怕某个决定后来被推翻了，
  那一条也留在原地 —— 推翻它的那一条会写在后面并指回去（比如 §0.1 推翻了 §0、
  §35.2 推翻了 §32 对遮挡的判断）。
- **有一批条目讲的是已下线的安卓客户端**（2026-08-05 下线，见 §36.1）。它们对现在的
  代码不再有约束力，只在你想知道"当初为什么那样做"时有用：

  | 条目 | 讲什么 | 现在还成立吗 |
  |---|---|---|
  | §9.1 | ARCore 运行时打进 APK（213 行） | ❌ 纯安卓打包 |
  | §14 | 整库 `.imgdb` 一直是坏的 | ❌ 那个接口没有消费者了 |
  | §15 | 保存到系统相册 | ❌ Android MediaStore |
  | §18 | 管理台内嵌进 App | ❌ 网页版 `/admin` 同源同会话，这些代价一个都不存在 |
  | §31 | WebView 里 `<input type=file>` 默认什么都不做 | ❌ 只是 WebView 的坑 |
  | §9 / §9.3 / §32 / §33 | ARCore 的 6DoF 位姿与贴合 | ⚠️ 结论不适用（网页版走单应矩阵四角那条纯 2D 路），但**里面对"贴不上有哪几种原因"的分析仍然成立** |
  | §13 | 打印宽度从必填改成可选 | ⚠️ 网页版根本不看这个数，它现在是纯元数据（见 `printsize.js`） |

  其余条目（识别特征、阈值怎么量的、用户与权限、一键部署、入库闸门、去重、
  管理台、批量导入、第 10～13 轮）**全部仍然有效** —— 它们讲的是服务端和识别，
  而那两块没有变。

## 不在这里的

- **`§N` 引用的那份内部设计文档没有随仓库发布。** 每处注释都把真正的理由写在了旁边，
  所以不看它也不缺信息。
- `docs/superpowers/` 是过程产物（spec / plan），在 `.gitignore` 里。
- 安卓客户端的源码在 git 历史里（`android/`）。
